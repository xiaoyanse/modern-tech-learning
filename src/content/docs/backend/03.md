## 六种生态在同一项目里各能做什么

| 语言 | 从哪类需求出发 | 代表项目 | 选型时先确认 |
| --- | --- | --- | --- |
| Python | 把 AI、数据处理或内部流程做成服务 | [FastAPI 文档](https://fastapi.tiangolo.com/) · [GitHub](https://github.com/fastapi/fastapi)；[Django 文档](https://docs.djangoproject.com/) · [GitHub](https://github.com/django/django) | 轻量 API 可看 FastAPI。需要内置管理界面、ORM 和认证体系时可看 Django。模型或原生依赖要在生产镜像上实测 |
| Rust | 网络服务、边缘代理、资源受限组件 | [axum 文档](https://docs.rs/axum/latest/axum/) · [GitHub](https://github.com/tokio-rs/axum)；[Tokio 文档](https://tokio.rs/) · [GitHub](https://github.com/tokio-rs/tokio) | axum 组织 HTTP 接口，Tokio 提供异步运行时。团队需有能力定位异步和跨平台构建问题 |
| C++ | 复用设备 SDK、做图像处理或低延迟计算 | [OpenCV 项目文档入口](https://github.com/opencv/opencv/wiki) · [GitHub](https://github.com/opencv/opencv)；[Drogon GitHub 与文档入口](https://github.com/drogonframework/drogon) | 先核对厂商支持的系统和编译器，测试异常断线、重连、依赖分发和 ABI 兼容性 |
| Java | 事务业务、权限集成、企业内部服务 | [Spring Boot 文档](https://docs.spring.io/spring-boot/index.html) · [GitHub](https://github.com/spring-projects/spring-boot) | 现有 JVM 平台、数据库与发布流程能否复用。根据启动时间、内存和流量实测部署方式 |
| Go | 网络服务、采集转发、后台工具 | [Go 文档](https://go.dev/doc/) · [GitHub](https://github.com/golang/go)；[Gin 文档](https://gin-gonic.com/en/docs/) · [GitHub](https://github.com/gin-gonic/gin) | 简单服务可先看标准库，路由和中间件需求增加时再看框架。引入 C 依赖后，部署仍需核对目标环境 |
| C# | .NET 业务服务、内部平台、既有 .NET SDK 集成 | [ASP.NET Core 文档](https://learn.microsoft.com/aspnet/core/) · [GitHub](https://github.com/dotnet/aspnetcore) | ASP.NET Core 可跨平台部署。Windows 专用驱动或旧组件仍需核对各自支持范围 |

## 设备巡检的选型结果

假设工厂已经有 Java 用户与权限平台，相机 SDK 仅提供 C++ 接口，后续想加入 Python 缺陷检测模型。首版可以让 Spring Boot 继续负责巡检记录和权限，让 C++ 现场进程负责相机。两边通过简单接口交换设备编号、时间戳和检测结果。Python 模型在有明确检测需求和样本后再接入。

如果换成小团队做独立试点，没有现成 Java 系统，模型分析又是主要功能，先做 Python API 和任务处理也合理。相机仍能由 C++ 进程接入。同样的接口边界给了不同团队选择业务框架的余地。

## 用真实环境核对生态

评估候选项目时，先确认它能接入现有身份、数据库和运行环境，再检查版本支持、依赖许可证、发布方式、测试和监控工具。用一个实际相机或真实样本走一条完整路径：采集、写记录、查结果、故障恢复。某个框架功能很多，但只要关键 SDK 无法在生产设备运行，就需要换边界或换方案。
