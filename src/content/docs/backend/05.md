**规划中 · 第 05 节大纲**

拟用三组案例讨论引入第二种语言的条件，每组都比较单语言基线与进程内、进程外方案。

| 组合 | 拟讨论场景与收益 | 候选边界 | 需要验证 |
| --- | --- | --- | --- |
| Java + C++ | Java 处理业务流程，复用已有 C++ 设备 SDK 或计算库 | 进程内用 JNI，或用 Java FFM 调用兼容的 C 接口。也可将 SDK 放入独立进程，通过 gRPC 交互 | 原生崩溃是否影响 JVM、接口与平台兼容性、驱动和部署 |
| Python + Rust | Python 做数据或任务编排，Rust 封装已测出的 CPU 热点 | PyO3 扩展模块，也可把任务放到独立工作进程 | 数据复制、线程与 Python 解释器的交互、构建和分发成本 |
| Python + C++ | Python 负责流程与模型调度，复用 C++ 图像算法或硬件 SDK | pybind11 绑定，或使用独立进程与 RPC | 内存所有权、异常和崩溃影响、平台 ABI 与 SDK 版本 |

拟对照 **FFI（外部函数接口）**、**IPC（进程间通信）** 和网络服务。比较时记录调用频率、每次传输的数据量、能否一起部署、是否需要故障隔离，以及调用失败后由谁恢复。

候选参考：[Java FFM](https://docs.oracle.com/en/java/javase/25/core/foreign-function-and-memory-api.html) · [PyO3 文档](https://pyo3.rs/) · [PyO3 GitHub](https://github.com/PyO3/pyo3) · [pybind11 文档](https://pybind11.readthedocs.io/en/stable/) · [pybind11 GitHub](https://github.com/pybind/pybind11) · [gRPC GitHub](https://github.com/grpc/grpc)
