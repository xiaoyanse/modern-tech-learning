这一期我们认识 **20 项端侧 AI 领域的代表技术与开源项目**。

不讲复杂算法、不要求你掌握 CUDA 编程，也不深入驱动开发。我们只解决三个问题：

- 一款 AI 模型如何从服务器搬到普通电脑、工业平板、手机或嵌入式设备？
- GPU、NPU、推理引擎、模型量化分别解决什么问题？
- 当你让 AI 开发一个本地运行的智能软件时，应该提醒它考虑哪些技术？

## 一、先建立全局认知

**端侧 AI（Edge AI / On-device AI）**，简单理解就是让 AI 尽可能在设备本地完成推理，而不必每次都把数据发送到云端。

## 端侧 AI 技术全景图

一个重要的认知：

**模型、推理引擎、硬件加速器是三个不同的东西。**

例如 YOLO 是模型，ONNX Runtime 是推理引擎，NVIDIA GPU 是计算硬件。

模型能否运行在某种硬件上，取决于推理引擎、硬件后端、算子支持、模型格式和设备驱动等条件，而不是简单地看模型文件能否复制过去。

## 二、第一组：通用推理引擎（1-5）

这一组可以理解为让 AI 模型在不同硬件上运行的软件工具。

| 技术 | 是什么 | 什么时候提示 AI 考虑 |
|--------|--------|--------|
| **1. ONNX Runtime** | 跨平台 AI 推理引擎 | 模型需要在 Windows、Linux、CPU、GPU 等环境运行 |
| **2. TensorRT** | NVIDIA GPU 专用的推理优化与执行 SDK | 使用 NVIDIA 显卡，希望获得更高推理性能 |
| **3. OpenVINO** | Intel 主导的推理与优化工具套件 | 使用 Intel CPU、核显、独显或受支持的 NPU |
| **4. LiteRT** | Google 的端侧机器学习运行框架，继承 TensorFlow Lite 生态 | 开发 Android、移动端或跨平台轻量 AI 应用 |
| **5. NCNN** | 腾讯开源的轻量神经网络推理框架 | Android、ARM 设备、移动端视觉模型，特别是希望减少运行依赖时 |

ONNX Runtime 用执行提供程序连接不同后端。LiteRT 面向端侧运行，OpenVINO 面向受支持的 Intel 硬件。选型时应查看目标设备、模型格式和算子覆盖。

**开源项目与官方入口**

## 三、第二组：NPU 与专用硬件适配（6-10）

NPU（Neural Processing Unit）是一类专门针对神经网络计算优化的硬件加速器。

它的主要价值通常是**在较低功耗下高效运行特定 AI 模型**。

但 NPU 不一定比 GPU 更快，也不一定支持所有模型。

**6. RKNN Toolkit2 / RKNPU2**

瑞芯微 Rockchip 的 NPU 模型转换和推理工具体系。

**想到它：** 在 RK3588、RK3568 等受支持芯片上运行 YOLO、分类、分割等模型。

成熟的芯片专用路线，具体模型需要适配。旧仓库已迁移到新组织。

[官方 GitHub](https://github.com/airockchip/rknn-toolkit2)

---

**7. Qualcomm QNN SDK**

高通的 AI 推理软件接口，帮助模型利用 Snapdragon 平台上的 AI 加速硬件。

**想到它：** 开发 Snapdragon 手机、工业终端或其他高通平台的本地 AI。

成熟厂商生态，SDK 与硬件支持需核对。

[Qualcomm AI Hub 示例项目](https://github.com/qualcomm/ai-hub-apps)

---

**8. Apple Core ML**

苹果设备的机器学习框架，可以利用受支持的 CPU、GPU 和 Neural Engine。

**想到它：** 开发 iPhone、iPad、Mac 上的本地视觉识别和 AI 功能。

成熟平台技术。

[Core ML Tools](https://github.com/apple/coremltools)

---

**9. Windows ML**

Microsoft 在 Windows 上提供的机器学习运行能力，帮助应用利用受支持的本地硬件加速。

**想到它：** 希望 Windows AI 软件适配不同品牌的 CPU、GPU、NPU，而不是绑定单一硬件厂商。

正在发展的 Windows AI 统一部署路线。

[Microsoft 官方文档](https://learn.microsoft.com/en-us/windows/ai/new-windows-ml/overview)

---

**10. Huawei CANN / AscendCL**

华为昇腾 AI 处理器的软件计算与推理工具体系。

**想到它：** 需要在昇腾硬件上部署视觉模型、大模型或其他 AI 应用。

成熟的专用硬件生态，但不同型号和模型的适配差异需要核实。

[Ascend CANN 官方入口](https://www.hiascend.com/cann)

这一组最重要的认识是：

**选择 NPU 时，不仅要看芯片标称 TOPS，还要看有没有成熟的模型转换工具、支持哪些算子，以及模型在实际设备上的速度和精度。**

例如一款 NPU 标称 20 TOPS，不意味着它一定能以预期速度运行任意 VLM 或 YOLO 模型。

## 四、第三组：模型轻量化技术（11-15）

这是端侧 AI 中非常重要的一类技术。

它们的共同目标是：让模型更小、更快、更省内存，或者降低推理功耗。

### 五种常见模型优化方式

| 方法 | 主要作用 | 验证指标 |
| --- | --- | --- |
| 11. 量化 | 用更低精度表示权重或激活 | 精度损失、端到端时延、峰值内存 |
| 12. 剪枝 | 减少参数或计算结构 | 目标设备能否实际加速 |
| 13. 知识蒸馏 | 用教师模型帮助训练更小的学生模型 | 真实样本表现、训练成本 |
| 14. 计算图优化 | 融合或改写算子，减少调度和数据搬运 | 算子兼容性、后端回退 |
| 15. 参数高效微调 | 使用 LoRA、QLoRA 等减少适配成本 | 任务效果、适配器加载与发布方式 |

注意：LoRA 和 QLoRA 主要是参数高效微调技术，不是直接的推理加速技术。它们放在这里，是因为端侧模型开发经常也受到训练和适配成本限制。

### 代表性开源工具

| 工具 | 主要用途 | 项目地址 |
|--------|--------|--------|
| ONNX Runtime Quantization | ONNX 模型量化 | [GitHub](https://github.com/microsoft/onnxruntime) |
| Intel NNCF | 模型量化与压缩 | [GitHub](https://github.com/openvinotoolkit/nncf) |
| NVIDIA ModelOpt | NVIDIA 模型优化工具 | [GitHub](https://github.com/NVIDIA/Model-Optimizer) |
| Hugging Face PEFT | LoRA 等参数高效微调 | [GitHub](https://github.com/huggingface/peft) |

**成熟度：** 量化、蒸馏、图优化都是成熟技术路线；具体工具和低精度格式的硬件支持仍在快速发展。

## 五、第四组：本地大模型与轻量化运行（16-20）

前面主要讲的是传统视觉模型。现在我们看另一个快速发展的领域：

**让大语言模型、视觉语言模型直接在个人电脑、手机或边缘设备上运行。**

**16. llama.cpp** 成熟 · 持续发展

高效的本地大模型推理项目，支持多种硬件后端和量化模型，也支持部分多模态模型。

**想到它：** 希望在普通电脑上离线运行 LLM，减少对 Python 和大型推理服务框架的依赖。

[GitHub](https://github.com/ggml-org/llama.cpp)

---

**17. Ollama** 成熟 · 持续发展

让开发者方便地下载、管理和运行本地大模型，并提供调用接口。

**想到它：** 希望快速给软件增加离线聊天、文档问答或本地多模态理解能力。

[GitHub](https://github.com/ollama/ollama)

---

**18. MLC LLM** 发展中

利用编译优化等技术，把大模型部署到不同硬件和设备环境。

**想到它：** 想在手机、GPU 设备或其他端侧硬件上运行本地大模型。

[GitHub](https://github.com/mlc-ai/mlc-llm)

---

**19. ExecuTorch** 发展中 · 生态扩张

PyTorch 生态中的端侧推理运行时，面向手机、嵌入式设备和其他资源受限平台。

**想到它：** 模型来自 PyTorch，希望部署到移动端或嵌入式设备，并利用硬件加速后端。

[GitHub](https://github.com/pytorch/executorch)

---

**20. Apache TVM / MLC** 成熟研究基础 · 持续演进

面向机器学习的编译优化技术体系，帮助将模型计算映射到不同硬件。

**想到它：** 现有推理框架无法充分利用特殊硬件，或者需要深入优化模型执行性能。

[Apache TVM GitHub](https://github.com/apache/tvm)

这里要区分：

- llama.cpp 更偏向高效的本地模型推理。
- Ollama 更偏向方便地管理和使用本地模型。
- ExecuTorch 更偏向 PyTorch 模型的端侧部署。
- TVM 更偏向编译和底层计算优化。

它们并非全部处于同一个技术层次。

## 六、LiteRT 与 Windows ML 的选型线索

LiteRT 延续 TensorFlow Lite 的端侧部署生态。Windows ML 可使用 ONNX Runtime 和受支持的执行提供程序。微软将 DirectML 置于维护模式，新 Windows 应用应比较 Windows ML 的系统要求、驱动和设备兼容性。旧项目迁移前用目标机验证模型加载、算子支持及性能。参考 [LiteRT 文档](https://ai.google.dev/edge/litert) 和 [Windows ML 文档](https://learn.microsoft.com/en-us/windows/ai/new-windows-ml/overview)。

## 七、最实用的技术选型速查表

以后遇到端侧 AI 需求，你可以直接参考这张表。

| 你的需求 | 应该提示 AI 调查 |
|--------|--------|
| Windows 上运行 ONNX 模型 | ONNX Runtime、Windows ML |
| NVIDIA GPU 上追求高性能 | TensorRT、ONNX Runtime CUDA |
| Intel CPU、GPU、NPU 推理 | OpenVINO |
| RK3588 上使用 NPU | RKNN Toolkit2、RKNPU2 |
| Snapdragon 设备运行 AI | QNN、LiteRT |
| iPhone、iPad 本地 AI | Core ML |
| Android 端侧视觉模型 | LiteRT、NCNN、ExecuTorch |
| 普通电脑离线运行大模型 | llama.cpp、Ollama |
| 模型太大、显存不足 | INT8/INT4 量化、模型压缩 |
| 大模型效果好但端侧运行慢 | 小模型、蒸馏、量化 |
| 特殊芯片没有成熟推理支持 | TVM、厂商 SDK |
| 希望一套软件适配多种硬件 | ONNX Runtime、多后端抽象 |

这里还有一个选型原则：

**跨平台兼容和极致性能往往需要权衡。**

ONNX Runtime 这样的通用引擎有利于统一开发接口，但某些硬件专用引擎可能获得更好的性能或更完整的加速支持。

## 八、如何向 AI 提出更专业的端侧技术选型要求？

### 端侧 AI 技术调查提示词

```text
我需要在【设备型号、操作系统】上运行【AI 模型及任务】。

请先调查设备的 CPU、GPU、NPU 能力，以及当前可用的官方 SDK 和开源推理框架。

比较 ONNX Runtime、硬件专用推理引擎、LiteRT、OpenVINO 或其他适合的方案。

重点评估模型兼容性、转换难度、推理延迟、内存占用、功耗、量化精度损失、许可证和离线部署能力。

请区分已验证能力与理论支持，并给出推荐方案和替代方案。

不要直接编写代码。
```
