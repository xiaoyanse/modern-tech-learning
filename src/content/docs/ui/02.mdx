今天我们要解决一个非常实际的问题：

**为什么同样使用 React + Tailwind CSS + shadcn/ui，有些软件看起来像专业产品，有些却像十几个不同的软件拼在一起？**

答案通常不是技术框架，而是有没有建立统一的 **Design System（设计系统）**。

这节课你不需要学习 CSS，也不需要亲自设计按钮。学完后，你应该知道如何要求 AI 在开发前制定规范，并在开发过程中始终遵守。

## 一、什么是 Design System？

Design System 不只是颜色、字体和组件库。

它是一套完整的产品界面规则，通常包含以下五个部分：

## 设计系统的五个组成部分

设计令牌控制基础变量，组件规范定义外观与状态，布局模板统一页面结构，主题映射适配不同环境，治理流程负责文档、变更和验收。

你可以把设计系统理解成软件界面的“企业标准”。

就像一家汽车制造商不会让每个工程师自行决定螺丝规格一样，专业软件也不应该让每个页面自行决定按钮高度、弹窗风格和错误提示方式。

---

## 二、Design Tokens：统一视觉的基础

Design Tokens（设计令牌）是整个设计系统的基础。

它的作用是把颜色、字体、间距、圆角等设计决策定义为可以复用的变量。

例如：

| 类型 | 示例 | 控制什么 |
|--------|--------|--------|
| Color Tokens | Primary、Success、Danger | 主色、成功色、危险色 |
| Typography Tokens | Body、Heading、Caption | 字体大小、粗细、行高 |
| Spacing Tokens | 4、8、12、16、24 | 组件间距和页面留白 |
| Radius Tokens | Small、Medium、Large | 按钮、卡片、弹窗圆角 |
| Shadow Tokens | Low、Medium、High | 浮层、卡片的视觉层次 |
| Motion Tokens | Fast、Normal、Slow | 动画时长和过渡效果 |

重点不是记住这些英文，而是理解：

**当所有页面使用同一套 Tokens，修改一个设计决策，就能够让整个软件的相关组件保持一致。**

## 三、Component System：为什么要统一组件？

假设你的软件有 30 个页面。

其中 20 个页面都有表格，15 个页面都有弹窗，所有页面都有按钮。

如果每个页面都独立开发，AI 很容易产生：

- 有些按钮高度 32px，有些 40px。
- 有些弹窗右上角关闭，有些底部关闭。
- 有些表格使用蓝色状态标签，有些使用绿色。
- 有些删除操作需要二次确认，有些直接删除。

专业做法是建立共享组件。

### 组件库应该统一什么？

**共享组件库**

按钮 · 输入框 · 表格 · 弹窗 · 状态标签

对于 shadcn/ui，你可以要求 AI：

**以 shadcn/ui 作为基础组件来源，在项目中建立统一封装，不允许不同页面各自复制并修改出互不兼容的按钮、表格和弹窗。**

不过也不要过度封装。对于只使用一次的特殊界面，不一定需要强行抽象为通用组件。

## 四、Layout System：布局体系决定软件是否专业

设计系统不仅要统一颜色，还要统一页面结构。

比如一个典型管理平台，可能采用：

平台

页面标题

主要内容区域

典型管理软件的页面骨架示意：侧边导航、页面标题、指标卡片、内容区域。

一套布局体系通常要明确：

- 导航采用侧边栏还是顶部导航。
- 页面标题和操作按钮放在哪里。
- 内容区最大宽度与边距。
- 表格、筛选器和分页的布局规则。
- 弹窗与抽屉分别用于什么场景。
- 不同屏幕尺寸下如何调整布局。

最重要的是：**不要让 AI 每开发一个页面，就重新发明一次页面结构。**

## 五、Theme System：主题系统不只是深色模式

很多人以为主题系统就是浅色和深色切换。

实际上，主题系统还可能包括：

- 品牌主题：不同产品使用不同主色。
- 亮色与暗色：适应不同工作环境。
- 高对比度：改善可读性和可访问性。
- 紧凑与舒适密度：适应信息密集型业务。
- 多产品共享设计系统：同一公司不同产品保持统一体验。

一个好的主题系统应该使用语义化变量。

例如，不要让所有页面直接使用固定的 `#ffffff` 作为背景，而是定义“页面背景”“卡片背景”“主要文字”等语义角色。

这样切换暗色主题时，不需要逐个修改页面。

## 六、如何判断一个设计系统是否真正完整？

可以用下面的清单做初步检查。

- [ ] 颜色、字号、间距等令牌有统一来源。
- [ ] 共享组件覆盖焦点、加载、错误和禁用等状态。
- [ ] 主要页面有共用布局，并验证窄屏。
- [ ] 浅色、深色主题都检查对比度。
- [ ] 组件更新后有运行和审查流程。

这只是一个初步评估。真正的设计系统还应考虑可访问性、跨平台差异、版本管理和设计与代码的一致性。

## 七、如何让 AI 始终遵守统一 UI 规范？

这是本节课最有价值的部分。

我建议你在项目开始时，让 AI 先完成三件事：

**第一，建立设计规范文档。**

明确颜色、字体、间距、圆角、组件、布局、交互和主题规则。

**第二，建立共享组件。**

要求新页面优先复用已有组件，不允许无理由重复开发。

**第三，建立 UI 审查机制。**

每完成一个页面，都检查它是否符合设计规范，而不是只检查功能能否运行。

你可以直接复制下面这段提示词。

### 统一 UI 设计系统提示词

```text
请为当前软件建立一套完整、统一、可维护的 Design System。

先审查现有 UI 技术栈和组件，不要直接重写页面。

请定义：

- Design Tokens：颜色、字体、间距、圆角、阴影、动效。
- 共享组件规范：按钮、表格、弹窗、表单、状态标签。
- 页面布局规范：导航、内容区域、表格和操作区。
- 交互状态规范：加载、成功、失败、空状态、禁用。
- 主题系统与可访问性要求。

优先复用现有组件，避免重复实现。

输出设计规范文档、组件清单、页面模板和一致性检查清单。

后续开发新页面必须遵守规范，新增组件或修改规范时应先说明原因与影响范围。
```

## 八、本课最重要的五个认知

1. **Design System 不等于 UI 组件库。** 组件库只是设计系统的一部分。
2. **Design Tokens 是视觉统一的基础。** 它们让全局调整成为可能。
3. **共享组件负责交互和外观一致。** 不应该让每个页面独立开发按钮、表格和弹窗。
4. **布局体系决定页面之间是否协调。** 统一的导航和内容结构非常重要。
5. **设计系统必须能够持续执行。** 只写一份规范文档，却不检查实际页面，是不够的。
