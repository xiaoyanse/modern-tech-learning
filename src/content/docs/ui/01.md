今天我们解决一个很实用的问题：

**当你准备让 AI 开发一款软件时，应该怎样选择 React、Tailwind CSS、shadcn/ui、Tauri、ECharts 等技术，才能既有专业的界面，又不引入重复或不必要的框架？**

我们不学习代码，而是建立一张完整的 UI 技术地图。

## 一、首先理解：UI 技术不是单选题，而是组合题

假设你要开发一款 Windows 桌面软件，界面包含侧边栏、表格、弹窗、图表和设备管理功能。

你完全可以采用下面的组合：

### 一套现代桌面 UI 技术组合

**React**

组织页面、交互和界面状态

**Tailwind CSS**

布局、颜色、间距、样式

**shadcn/ui**

按钮、弹窗、表单、菜单

**Tauri**

桌面窗口、安装包和系统集成

这些技术之所以能组合，是因为它们大多处在不同的职责层。

你可以把它理解为组建一支团队：React 负责组织界面，Tailwind 负责样式，shadcn/ui 提供现成组件，ECharts 负责图表，Tauri 负责桌面运行环境。

但并不是每个项目都需要所有成员。

## 二、认识 UI 技术栈的六个层次

| 层次 | 职责 | 候选 |
| --- | --- | --- |
| 界面框架 | 状态与页面结构 | React、Vue |
| 样式体系 | 间距、布局、响应式 | Tailwind CSS、CSS Modules |
| 基础组件 | 表单、对话框、按钮 | shadcn/ui、Radix UI、Ant Design |
| 专业组件 | 图表、数据表格、编辑画布 | ECharts、TanStack Table、Konva |
| 运行环境 | 桌面窗口、系统集成、安装 | Tauri、Electron |
| 设计系统 | 统一外观、行为、可访问性和维护规范 | 语义令牌、组件规则和页面模板 |

| 层次 | 主要解决什么问题 | 代表技术 |
|--------|--------|--------|
| 1. 界面框架 | 页面如何组织、交互如何响应 | React、Vue、Svelte |
| 2. 样式体系 | 颜色、排版、布局、响应式 | Tailwind CSS、CSS |
| 3. 基础组件 | 按钮、输入框、弹窗、菜单 | shadcn/ui、MUI、Ant Design |
| 4. 专业组件 | 表格、图表、编辑器、复杂绘图 | TanStack Table、ECharts、Monaco、PixiJS |
| 5. 桌面运行环境 | 安装包、窗口、系统能力 | Tauri、Electron、Qt |
| 6. 设计系统 | 让整个软件保持统一的视觉与交互规则 | Design Tokens、组件规范、Figma |

这里有一个很重要的区别：

**第 6 层设计系统不是再安装一个框架，而是为前面所有技术制定统一规范。**

例如你可以要求所有表格、弹窗和按钮使用相同的字体、圆角、间距、颜色和交互规则。

## 三、哪些技术适合组合，哪些容易重复？

React + Tailwind CSS + shadcn/ui 分别处理页面、样式和组件。两套基础组件库通常会重复维护主题与交互。同一产品可以用 ECharts 绘制统计图，用 Three.js 渲染三维场景，因为两者服务于不同任务。

| 技术组合 | 判断 | 原因 |
|--------|--------|--------|
| React + Tailwind | 推荐 | 界面逻辑和样式互补 |
| Tailwind + shadcn/ui | 推荐 | shadcn/ui 通常基于 Tailwind 样式 |
| shadcn/ui + Radix UI | 合理 | Radix 可作为底层交互组件基础 |
| shadcn/ui + TanStack Table | 推荐用于复杂表格 | 前者提供外观，后者提供表格逻辑 |
| React + ECharts | 合理 | React 负责页面，ECharts 负责图表 |
| React + Tauri | 合理 | Web 界面与桌面容器组合 |
| React + Vue | 通常不推荐 | 两套 UI 框架增加维护成本 |
| shadcn/ui + Ant Design 全量混用 | 谨慎 | 容易出现两套组件规范 |
| Tauri + Electron | 通常不需要 | 两者主要解决同一类桌面封装问题 |

无头组件提供状态、交互和键盘行为，视觉样式由项目设计系统决定。Headless UI 也是其中一个具体库的名称。

它通常只提供交互行为，不强制规定外观。例如 TanStack Table 主要负责排序、筛选、分页等表格逻辑，外观可以由 shadcn/ui 或你自己的组件实现。官方文档也明确支持这种组合。

这意味着你可以拥有复杂功能，同时保持自己的视觉风格。

## 四、通过三个场景理解如何选型

**场景 A：普通企业管理后台**

推荐候选：

React + Vite + Tailwind CSS + shadcn/ui

如果需要复杂表格，增加 TanStack Table；如果需要数据图表，增加 ECharts。

**判断：** 不需要桌面安装包，就没必要引入 Tauri。

---

**场景 B：Windows 桌面监控软件**

推荐候选：

React + Tailwind CSS + shadcn/ui + Tauri + Rust

根据实际需求增加实时图表、二维绘制或视频组件。

**判断：** Tauri 官方支持 React 等前端框架，并推荐 Vite 用于常见单页应用。

---

**场景 C：三维数字孪生平台**

推荐候选：

React + Tailwind CSS + Three.js

普通按钮、表单可以继续使用 shadcn/ui，三维区域交给 Three.js。

**判断：** 不应该用普通 HTML 组件去代替专门的三维渲染引擎。

注意，以上都是候选组合，而不是固定标准答案。

## 五、拆解一个设备中心

| 界面区域 | 技术职责 |
| --- | --- |
| 「概览」「设备列表」切换 | React 保存状态、切换内容 |
| 顶部「添加设备」和确认对话框 | 使用同一套 shadcn/ui 组件 |
| 不同宽度下的布局和间距 | Tailwind CSS 和语义令牌 |
| 趋势图与设备表格 | 按数据规模选择 ECharts 和适合的表格工具 |

本站使用 Starlight 生成课程页面。学习进度与提示词按钮使用 React、Tailwind CSS 和 shadcn/ui，可作为同一套设计规范连接不同实现层的例子。

## 六、如何避免 AI 开发 UI 时出现技术混乱？

以后你可以向 AI 提出四项要求：

1. **确定一个主 UI 框架。** 例如 React，不要无故混用 Vue。
2. **确定一个主要组件体系。** 例如 shadcn/ui，不要每个页面换一套组件库。
3. **按需增加专业组件。** 只有复杂表格才引入 TanStack Table，有三维需求才引入 Three.js。
4. **建立统一设计规范。** 所有页面使用相同的设计变量、组件封装和交互标准。

尤其要注意：技术组合越多，不代表 UI 越先进。

一个只有 React + Tailwind + shadcn/ui 的软件，也完全可以拥有非常专业的界面。

## 七、可以直接复制的 AI 技术选型提示词

### 现代 UI 技术组合规划

```text
我准备开发一款【软件类型】，运行平台是【平台】，界面包含【主要页面与功能】。

请先规划 UI 技术栈，区分界面框架、样式体系、基础组件、专业组件、桌面运行环境和设计系统。

优先考虑成熟、可组合的开源技术，避免职责重复。

请说明每项技术解决什么问题、为什么需要、有哪些替代方案。

特别检查组件风格一致性、维护成本、许可证和跨平台兼容性。

先输出技术组合与统一设计规范建议，不要直接开始编写页面代码。
```
